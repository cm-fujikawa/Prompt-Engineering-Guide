プロンプトを設計する際に留意すべきヒントをいくつか紹介します。

### シンプルに始める

プロンプトのデザインを始めるときは、それが実際には反復的なプロセスであり、最適な結果を得るには多くの実験が必要であることに留意する必要があります。 OpenAI または Cohere のシンプルなプレイグラウンドを使用するのが良い出発点です。

単純なプロンプトから始めて、より良い結果を目指して要素やコンテキストを追加し続けることができます。このため、途中でプロンプトを繰り返すことが重要です。このガイドを読むと、具体性、単純さ、簡潔さがより良い結果をもたらす例がたくさん出てきます。

多くの異なるサブタスクを伴う大きなタスクがある場合は、タスクをより単純なサブタスクに分割し、より良い結果が得られるようにサブタスクを積み上げていくことができます。これにより、最初のプロンプト設計プロセスが複雑になりすぎることがなくなります。

### 指示

「書き込み」、「分類」、「要約」、「翻訳」、「順序付け」など、達成したいことをコマンドを使用してモデルに指示することで、さまざまな単純なタスクに効果的なプロンプトを設計できます。

何が最も効果的かを知るには、多くの実験を行う必要があることにも留意してください。さまざまなキーワード、コンテキスト、データを使用してさまざまな手順を試し、特定のユースケースやタスクに最適なものを確認してください。通常、コンテキストが実行しようとしているタスクに具体的で関連性が高いほど、より良い結果が得られます。今後のガイドでは、サンプリングとコンテキストの追加の重要性について触れます。

プロンプトの先頭に指示を置くことを推奨する人もいます。もう 1 つの推奨事項は、「###」のような明確な区切り文字を使用して命令とコンテキストを区切ることです。

例えば：

*プロンプト：*

```
### Instruction ###
Translate the text below to Spanish:

Text: "hello!"
```

*出力：*

```
¡Hola!
```

### 特異性

モデルに実行してもらいたい指示とタスクについては、非常に具体的にします。プロンプトがよりわかりやすく詳細であればあるほど、より良い結果が得られます。これは、求める結果や生成スタイルがある場合に特に重要です。より良い結果をもたらす特定のトークンやキーワードはありません。適切な形式と説明的なプロンプトを用意することがより重要です。実際、プロンプトに例を提供することは、特定の形式で目的の出力を得るのに非常に効果的です。

プロンプトの長さには制限があるため、プロンプトを設計するときは、プロンプトの長さにも留意する必要があります。どこまで具体的かつ詳細に伝えるべきかを考えます。不必要な詳細をあまりにも多く含めることは、必ずしも良いアプローチであるとは限りません。詳細は関連性があり、当面のタスクに貢献する必要があります。これは何度も試してみる必要があります。アプリケーションのプロンプトを最適化するために、多くの実験と反復を行うことをお勧めします。

例として、テキストから特定の情報を抽出するための簡単なプロンプトを試してみましょう。

*プロンプト：*

```
Extract the name of places in the following text. 

Desired format:
Place: <comma_separated_list_of_places>

Input: "Although these developments are encouraging to researchers, much is still a mystery. “We often have a black box between the brain and the effect we see in the periphery,” says Henrique Veiga-Fernandes, a neuroimmunologist at the Champalimaud Centre for the Unknown in Lisbon. “If we want to use it in the therapeutic context, we actually need to understand the mechanism.“"
```

*出力：*

```
Place: Champalimaud Centre for the Unknown, Lisbon
```

入力テキストは次から取得されます[このネイチャーの記事](https://www.nature.com/articles/d41586-023-00509-z).

### 不正確さを避ける

詳細化とフォーマットの改善に関する上記のヒントを考慮すると、プロンプトについてあまりにも賢くなりすぎて、潜在的に不正確な説明を作成してしまうという罠に陥りがちです。多くの場合、具体的かつ直接的な方が良いでしょう。ここでの例えは、効果的なコミュニケーションと非常によく似ています。つまり、直接的であればあるほど、メッセージはより効果的に伝わります。

たとえば、プロンプト エンジニアリングの概念を学ぶことに興味があるかもしれません。次のようなことを試してみるとよいでしょう:

```
Explain the concept prompt engineering. Keep the explanation short, only a few sentences, and don't be too descriptive.
```

上記のプロンプトからは、使用する文の数とスタイルは明らかではありません。上記のプロンプトでもある程度は良好な応答が得られるかもしれませんが、より適切なプロンプトは、非常に具体的で、簡潔で、要点を押さえたものになります。次のようなもの:

```
Use 2-3 sentences to explain the concept of prompt engineering to a high school student.
```

### やるかやらないか？

プロンプトをデザインするときのもう 1 つの一般的なヒントは、「してはいけないこと」を言わずに、代わりに「すべきこと」を言うことです。これにより、より具体性が高まり、モデルからの良好な応答につながる詳細に焦点が当てられます。

これは、映画の推奨チャットボットが、私が指示を書いた方法が原因で、まさに私が実行してほしくないこと、つまり「してはいけないこと」に焦点を当てて失敗した例です。

*プロンプト：*

```
The following is an agent that recommends movies to a customer. DO NOT ASK FOR INTERESTS. DO NOT ASK FOR PERSONAL INFORMATION.

Customer: Please recommend a movie based on my interests.
Agent: 
```

*出力：*

```
Sure, I can recommend a movie based on your interests. What kind of movie would you like to watch? Do you prefer action, comedy, romance, or something else?
```

より良いプロンプトは次のとおりです。

*プロンプト：*

```
The following is an agent that recommends movies to a customer. The agent is responsible to recommend a movie from the top global trending movies. It should refrain from asking users for their preferences and avoid asking for personal information. If the agent doesn't have a movie to recommend, it should respond "Sorry, couldn't find a movie to recommend today.".

Customer: Please recommend a movie based on my interests.
Agent:
```

*出力：*

```
Sorry, I don't have any information about your interests. However, here's a list of the top global trending movies right now: [list of movies]. I hope you find something you like!
```
