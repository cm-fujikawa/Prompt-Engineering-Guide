## Prompting an LLM

単純なプロンプトで多くのことを達成できますが、結果の品質は、提供する情報の量とプロンプトがどれほど巧妙に作成されているかによって決まります。プロンプトには次のような情報を含めることができます。*命令* or *質問*モデルに渡しており、次のような他の詳細を含めます。*コンテクスト*, *入力*、 または*例*。これらの要素を使用すると、モデルにより効果的に指示して結果の品質を向上させることができます。

まずは、単純なプロンプトの基本的な例を見てみましょう。

*プロンプト*

```md
The sky is
```

*出力：*

```md
blue.
```

OpenAI Playground またはその他の LLM プレイグラウンドを使用している場合は、次のスクリーンショットに示すようにモデルにプロンプ​​トを表示できます。

注意すべき点は、次のような OpenAI チャット モデルを使用する場合です。`gpt-3.5-turbo` or `gpt-4`では、次の 3 つの異なる役割を使用してプロンプトを構成できます。`system`, `user`、 そして`assistant`。システム メッセージは必須ではありませんが、アシスタントの全体的な動作を設定するのに役立ちます。上の例には、モデルに直接プロンプトを表示するために使用できるユーザー メッセージのみが含まれています。わかりやすくするために、明示的に言及されている場合を除き、すべての例では、`user`を促すメッセージ`gpt-3.5-turbo`モデル。の`assistant`上記の例のメッセージはモデル応答に対応します。アシスタント メッセージを定義して、必要な動作の例を渡すこともできます。チャットモデルの操作について詳しく学ぶことができます[ここ](https://www.promptingguide.ai/models/chatgpt).

上記のプロンプトの例から、言語モデルがコンテキストを考慮して意味のある一連のトークンで応答することがわかります。`"The sky is"`。出力は予期しないものであるか、達成したいタスクとはかけ離れている可能性があります。実際、この基本的な例は、システムで具体的に何を達成したいのかについて、より多くのコンテキストや指示を提供する必要性を強調しています。これがプロンプトエンジニアリングのすべてです。

それを少し改善してみましょう:

*プロンプト：*

```
Complete the sentence: 

The sky is
```

*出力：*

```
blue during the day and dark at night.
```

その方が良いでしょうか？上記のプロンプトでは、モデルに文を完成するように指示しているため、モデルに指示したこと (「文を完成する」) に正確に従うため、結果の見栄えが大幅に向上します。モデルに目的のタスクを実行するように指示する効果的なプロンプトを設計するこのアプローチは、と呼ばれるものです。**プロンプトエンジニアリング**このガイドでは。

上の例は、今日の LLM で何ができるかを示す基本的な図です。今日の LLM は、テキストの要約から数学的推論、コード生成に至るまで、あらゆる種類の高度なタスクを実行できます。

## プロンプトフォーマット

上記の非常に単純なプロンプトを試してみました。標準プロンプトの形式は次のとおりです。

```
<Question>?
```

or

```
<Instruction>
```

これを、次のように、多くの QA データセットで標準である質問応答 (QA) 形式にフォーマットできます。

```
Q: <Question>?
A: 
```

上記のようなプロンプトを表示する場合、次のように呼ばれます。*Zero-Shotプロンプト*つまり、モデルに達成させたいタスクに関する例やデモンストレーションを行わずに、モデルに直接応答を求めています。一部の大規模な言語モデルにはゼロショット プロンプトを実行する機能がありますが、それは目の前のタスクの複雑さと知識、およびモデルが適切に実行するようにトレーニングされたタスクに依存します。

具体的なプロンプトの例は次のとおりです。

*プロンプト*

```
Q: What is prompt engineering?
```

最近のモデルの一部では、「Q:」部分は、シーケンスの構成方法に基づいて質問応答タスクとして暗示され、モデルによって理解されるため、この部分をスキップできます。つまり、プロンプトは次のように簡略化できます。

*プロンプト*

```
What is prompt engineering?
```

上記の標準形式を考慮すると、プロンプトに対する一般的で効果的な手法の 1 つは、次のように呼ばれます。*Few-Shotプロンプト*見本（つまり、デモンストレーション）を提供する場合。数回のプロンプトは次のようにフォーマットできます。

```
<Question>?
<Answer>

<Question>?
<Answer>

<Question>?
<Answer>

<Question>?

```

QA 形式のバージョンは次のようになります。

```
Q: <Question>?
A: <Answer>

Q: <Question>?
A: <Answer>

Q: <Question>?
A: <Answer>

Q: <Question>?
A:
```

QA 形式を使用する必要はないことに注意してください。プロンプトの形式は、実行中のタスクによって異なります。たとえば、次のように単純な分類タスクを実行し、そのタスクを示すサンプルを提供することができます。

*プロンプト：*

```
This is awesome! // Positive
This is bad! // Negative
Wow that movie was rad! // Positive
What a horrible show! //
```

*出力：*

```
Negative
```

少数のショット プロンプトにより、コンテキスト内学習が可能になります。これは、言語モデルがいくつかのデモンストレーションを行ってタスクを学習する能力です。今後のセクションでは、ゼロショット プロンプトと少数ショット プロンプトについてさらに詳しく説明します。
