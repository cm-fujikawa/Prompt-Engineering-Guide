# LLM Tokenization

Andrej Karpathy 氏は最近、新しい論文を出版しました。[講義](https://youtu.be/zduSFxRajkE?si=Hq_93DBE72SQt73V)大規模言語モデル (LLM) のトークン化について。トークン化は LLM のトレーニングの重要な部分ですが、独自のデータセットとアルゴリズム (例:[バイトペアエンコーディング](https://en.wikipedia.org/wiki/Byte_pair_encoding)).

講義では、Karpathy が GPT トークナイザーを一から実装する方法を教えます。彼はまた、トークン化に遡る奇妙な動作についても説明しています。

!["LLM Tokenization"](../../img/research/tokenization.png)

*図出典：https://youtu.be/zduSFxRajkE?t=6711*

上記のリストのテキスト版は次のとおりです。

- なぜ LLM は単語を綴ることができないのでしょうか?トークン化。
- なぜ LLM は文字列を反転するなどの非常に単純な文字列処理タスクを実行できないのでしょうか?トークン化。
- LLM は英語以外の言語 (日本語など) が苦手なのはなぜですか?トークン化。
- LLM はなぜ単純な算術が苦手なのでしょうか?トークン化。
- GPT-2 では、Python でのコーディングに必要以上に苦労したのはなぜですか?トークン化。
- LLM が文字列「\<endoftext>」を見つけると突然停止するのはなぜですか?トークン化。
- 「末尾の空白」に関するこの奇妙な警告は何ですか?トークン化。
- 「SolidGoldコイキング」について質問すると、なぜLLMが壊れるのですか？トークン化。
- LLM では JSON ではなく YAML を使用する方がよいのはなぜですか?トークン化。
- LLM が実際にはエンドツーエンドの言語モデリングではないのはなぜですか?トークン化。
- 苦しみの本当の根源は何でしょうか？トークン化。

LLM の信頼性を向上させるには、これらのモデルをプロンプトする方法を理解することが重要です。これには、その制限の理解も必要です。トークナイザーにはあまり重点が置かれていませんが (`max_tokens`構成）推論時に、優れたプロンプト エンジニアリングには、プロンプトの構造やフォーマットの方法と同様に、トークン化に固有の制約と制限を理解することが含まれます。たとえば、適切に処理またはトークン化されていない頭字語や概念を理解できないために、プロンプトのパフォーマンスが低下するシナリオが考えられます。これは、多くの LLM 開発者や研究者が見落としている非常に一般的な問題です。

トークン化に適したツールは次のとおりです。[ティックトケナイザー](https://tiktokenizer.vercel.app/)これは実際に講義でデモンストレーションのために使用されたものです。
