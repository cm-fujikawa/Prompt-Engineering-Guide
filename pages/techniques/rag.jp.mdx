汎用言語モデルを微調整して、感情分析や固有表現認識などのいくつかの一般的なタスクを実行できます。これらのタスクには通常、追加の背景知識は必要ありません。

より複雑で知識集約的なタスクの場合は、外部の知識ソースにアクセスしてタスクを完了する言語モデルベースのシステムを構築できます。これにより、より事実との一貫性が可能になり、生成された応答の信頼性が向上し、「幻覚」の問題を軽減するのに役立ちます。

メタ AI 研究者は、と呼ばれる手法を導入しました。[Retrieval Augmented Generation (RAG)](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models/)このような知識集約的なタスクに対処します。 RAG は、情報検索コンポーネントとテキスト ジェネレーター モデルを組み合わせます。 RAG は微調整でき、その内部知識は効率的な方法で、モデル全体の再トレーニングを必要とせずに変更できます。

RAG は入力を受け取り、ソース (Wikipedia など) が指定された一連の関連/サポート文書を取得します。ドキュメントは、元の入力プロンプトとコンテキストとして連結され、最終出力を生成するテキスト ジェネレーターに供給されます。これにより、RAG は時間の経過とともに事実が変化する可能性がある状況に適応できるようになります。 LLM のパラメトリック知識は静的であるため、これは非常に役立ちます。 RAG を使用すると、言語モデルが再トレーニングをバイパスできるようになり、検索ベースの生成を通じて信頼性の高い出力を生成するための最新情報にアクセスできるようになります。

Lewis et al., (2021) proposed a general-purpose fine-tuning recipe for RAG. A pre-trained seq2seq model is used as the parametric memory and a dense vector index of Wikipedia is used as non-parametric memory (accessed using a neural pre-trained retriever). RAG は、次のようないくつかのベンチマークで優れたパフォーマンスを示します。[自然な質問](https://ai.google.com/research/NaturalQuestions), [ウェブ質問](https://paperswithcode.com/dataset/webquestions)、CuratedTrec。 RAG は、MS-MARCO および Jeopardy の質問についてテストすると、より事実に基づいた、具体的で多様な回答を生成します。 RAG は、FEVER 事実検証の結果も改善します。

これは、知識集約型タスクにおける言語モデルの出力を強化するための実行可能なオプションとして RAG の可能性を示しています。

最近では、これらの取得者ベースのアプローチがより一般的になり、機能と事実の一貫性を向上させるために ChatGPT などの人気のある LLM と組み合わせられています。
