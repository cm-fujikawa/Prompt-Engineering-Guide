# Reflexion

import { Callout } from 'nextra/components'

リフレクションは、言語フィードバックを通じて言語ベースのエージェントを強化するフレームワークです。によると[Shinn et al. (2023)](https://arxiv.org/pdf/2303.11366.pdf)、「リフレクションは、LLM パラメータの選択と組み合わせたエージェントのメモリ エンコーディングとしてポリシーをパラメータ化する、『言葉による』強化のための新しいパラダイムです。」

高レベルでは、Reflexion は環境からのフィードバック (自由形式言語またはスカラーのいずれか) を言語フィードバック (言語フィードバックとも呼ばれます) に変換します。**反省**これは、次のエピソードで LLM エージェントのコンテキストとして提供されます。これにより、エージェントは以前の間違いから迅速かつ効果的に学習し、多くの高度なタスクのパフォーマンスの向上につながります。

!["Reflexion Framework"](../../img/research/reflexion.png)

上の図に示すように、Reflexion は 3 つの異なるモデルで構成されています。

- **俳優**: 状態の観察に基づいてテキストとアクションを生成します。アクターは環境内でアクションを実行し、軌跡をもたらす観察を受け取ります。[思考連鎖 (CoT)](https://www.promptingguide.ai/techniques/cot)そして[ReAct](https://www.promptingguide.ai/techniques/react)アクターモデルとして使用されます。追加のコンテキストをエージェントに提供するために、メモリ コンポーネントも追加されます。
- **評価者**: アクターによって生成された出力をスコアリングします。具体的には、生成された軌跡 (短期記憶とも呼ばれる) を入力として受け取り、報酬スコアを出力します。タスクに応じて異なる報酬関数が使用されます (意思決定タスクには LLM とルールベースのヒューリスティックが使用されます)。
- **内省**: アクターの自己改善を支援するための言葉による強化キューを生成します。この役割は LLM によって実現され、将来のトライアルに貴重なフィードバックを提供します。メモリに保存される具体的で関連性のあるフィードバックを生成するために、自己反映モデルは報酬信号、現在の軌道、およびその永続的なメモリを利用します。これらの経験 (長期記憶に保存される) は、エージェントによって意思決定を迅速に改善するために活用されます。

要約すると、反射プロセスの主要なステップは、a) タスクの定義、b) 軌跡の生成、c) 評価、d) 反映の実行、および e) 次の軌跡の生成です。以下の図は、意思決定、プログラミング、推論などのさまざまなタスクを解決するために、リフレクション エージェントがその動作を反復的に最適化する方法を学習する方法の例を示しています。 Reflexion は、自己評価、自己反省、および記憶コンポーネントを導入することにより、ReAct フレームワークを拡張します。

!["Reflexion Examples"](../../img/research/reflexion-examples.png)

## 結果

実験結果は、Reflexion エージェントが AlfWorld の意思決定タスク、HotPotQA の推論質問、HumanEval の Python プログラミング タスクのパフォーマンスを大幅に向上させることを示しています。

逐次意思決定 (AlfWorld) タスクで評価した場合、ReAct + Reflexion は、バイナリ分類にヒューリスティックと GPT の自己評価手法を使用して 130/134 タスクを完了することで、ReAct を大幅に上回りました。

!["Reflexion ALFWorld Results"](../../img/research/reflexion-alfworld.png)

リフレクションは、いくつかの学習ステップにわたってすべてのベースライン アプローチよりも大幅に優れています。推論のみの場合、および最新の軌跡からなるエピソード記憶を追加した場合、反射 + CoT はそれぞれ CoT のみおよびエピソード記憶のある CoT よりも優れています。

!["Reflexion ALFWorld Results"](../../img/research/reflexion-hotpotqa.png)

以下の表にまとめられているように、Reflexion は一般に、MBPP、HumanEval、および Leetcode Hard での Python および Rust のコード作成における以前の最先端のアプローチよりも優れたパフォーマンスを発揮します。

## リフレクションをいつ使用するか?

リフレクションは次の場合に最適です。

1. **エージェントは試行錯誤から学ぶ必要がある**: Reflexion は、過去の間違いを振り返り、その知識を将来の意思決定に組み込むことで、エージェントのパフォーマンスを向上できるように設計されています。そのため、意思決定、推論、プログラミングなど、エージェントが試行錯誤を通じて学習する必要があるタスクに適しています。

2. **従来の強化学習手法は実用的ではない**: 従来の強化学習 (RL) 手法では、多くの場合、広範なトレーニング データと高価なモデルの微調整が必​​要です。 Reflexion は、基礎となる言語モデルを微調整する必要のない軽量の代替手段を提供し、データとコンピューティング リソースの点でより効率的になります。

3. **微妙なフィードバックが必要です**: リフレクションは口頭によるフィードバックを利用します。これは、従来の RL で使用されるスカラー報酬よりも、より微妙で具体的なものになる可能性があります。これにより、エージェントは自分の間違いをより深く理解し、その後のトライアルでより的を絞った改善を行うことができます。

4. **解釈可能性と明示的な記憶が重要**: リフレクションは、従来の RL 手法と比較して、より解釈可能かつ明示的な形式のエピソード記憶を提供します。エージェントの内省はメモリに保存されるため、学習プロセスの分析と理解が容易になります。

リフレクションは次のタスクに効果的です。

- **逐次的な意思決定**: リフレクション エージェントは、さまざまな環境をナビゲートし、複数のステップの目標を完了することを含む AlfWorld タスクのパフォーマンスを向上させます。
- **推論**: Reflexion により、複数のドキュメントに対する推論が必要な質問応答データセットである HotPotQA でのエージェントのパフォーマンスが向上しました。
- **プログラミング**: リフレクション エージェントは、HumanEval や MBPP などのベンチマークでより優れたコードを記述し、場合によっては最先端の結果を達成します。

Reflexion には次のような制限があります。

- **自己評価能力への依存**: リフレクションは、エージェントのパフォーマンスを正確に評価し、有用な自己リフレクションを生成する能力に依存しています。これは、特に複雑なタスクの場合には困難になる可能性がありますが、モデルの機能が向上し続けるにつれて、時間の経過とともに Reflexion が改善されることが期待されます。
- **長期記憶の制約**: Reflexion は最大容量のスライディング ウィンドウを利用しますが、より複雑なタスクの場合は、ベクトル埋め込みや SQL データベースなどの高度な構造を使用する方が有利な場合があります。
- **コード生成の制限事項**: 正確な入出力マッピングを指定するテスト駆動開発には制限があります (例: 非決定的なジェネレーター関数やハードウェアの影響を受ける関数出力)。
