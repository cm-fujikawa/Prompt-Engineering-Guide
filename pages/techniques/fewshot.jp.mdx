大規模言語モデルは優れたゼロショット機能を示していますが、ゼロショット設定を使用すると、より複雑なタスクにはまだ不十分です。フューショット プロンプトは、モデルのパフォーマンスを向上させるためのデモンストレーションをプロンプト内で提供する、コンテキスト内学習を可能にする手法として使用できます。デモンストレーションは、モデルに応答を生成させたい後続の例の条件付けとして機能します。

によると[Touvron et al. 2023](https://arxiv.org/pdf/2302.13971.pdf)モデルが十分なサイズにスケールされたときに初めて表示されるショット プロパティはほとんどありませんでした[(Kaplan et al., 2020)](https://arxiv.org/abs/2001.08361).

で示された例を使用して、数回のプロンプトを示してみましょう。[Brown et al. 2020](https://arxiv.org/abs/2005.14165)。この例では、タスクは文の中で新しい単語を正しく使用することです。

*プロンプト：*

```markdown
A "whatpu" is a small, furry animal native to Tanzania. An example of a sentence that uses the word whatpu is:
We were traveling in Africa and we saw these very cute whatpus.

To do a "farduddle" means to jump up and down really fast. An example of a sentence that uses the word farduddle is:
```

*出力：*

```
When we won the game, we all started to farduddle in celebration.
```

モデルが 1 つの例 (つまり、1 ショット) だけを提供することで、何らかの形でタスクの実行方法を学習したことがわかります。より難しいタスクの場合は、デモンストレーションの数を増やして実験できます (例: 3 ショット、5 ショット、10 ショットなど)。

からの調査結果に従って、[Min et al. (2022)](https://arxiv.org/abs/2202.12837)、ここでは、少数ショットを実行する際のデモンストレーション/模範に関するヒントをいくつか紹介します。

- 「ラベル空間とデモンストレーションで指定された入力テキストの分布は両方とも重要です (ラベルが個々の入力に対して正しいかどうかに関係なく)」
- 使用する形式もパフォーマンスに重要な役割を果たします。ランダムなラベルを使用するだけでも、ラベルをまったく使用しないよりははるかに優れています。
- 追加の結果は、(一様な分布ではなく) ラベルの真の分布からランダムなラベルを選択することも役立つことを示しています。

いくつかの例を試してみましょう。まず、ランダムなラベルを使用した例を試してみましょう (つまり、ラベル Negative と Positive が入力にランダムに割り当てられます)。

*プロンプト：*

```
This is awesome! // Negative
This is bad! // Positive
Wow that movie was rad! // Positive
What a horrible show! //
```

*出力：*

```
Negative
```

ラベルがランダム化されていても、依然として正しい答えが得られます。形式も保持していることに注意してください。これも役立ちます。実際、さらなる実験により、私たちが実験している新しい GPT モデルは、ランダムな形式に対してもより堅牢になっているようです。例：

*プロンプト：*

```
Positive This is awesome! 
This is bad! Negative
Wow that movie was rad!
Positive
What a horrible show! --
```

*出力：*

```
Negative
```

上記の形式には一貫性がありませんが、モデルは依然として正しいラベルを予測しました。これがさまざまなプロンプトのバリエーションを含む、より複雑なタスクに当てはまるかどうかを確認するには、より徹底的な分析を行う必要があります。

### 少数ショット プロンプトの制限

標準的な少数ショット プロンプトは多くのタスクにうまく機能しますが、特により複雑な推論タスクを扱う場合には、まだ完全なテクニックではありません。なぜそうなるのかを説明しましょう。次のタスクを提供した前の例を思い出してください。

```
The odd numbers in this group add up to an even number: 15, 32, 5, 13, 82, 7, 1. 

A: 
```

これを再試行すると、モデルは次のように出力します。

```
Yes, the odd numbers in this group add up to 107, which is an even number.
```

これは正しい対応ではなく、これらのシステムの限界を浮き彫りにするだけでなく、より高度な即時エンジニアリングの必要性を浮き彫りにしています。

いくつかの例を追加して、数回のプロンプトによって結果が改善されるかどうかを確認してみましょう。

*プロンプト：*

```
The odd numbers in this group add up to an even number: 4, 8, 9, 15, 12, 2, 1.
A: The answer is False.

The odd numbers in this group add up to an even number: 17,  10, 19, 4, 8, 12, 24.
A: The answer is True.

The odd numbers in this group add up to an even number: 16,  11, 14, 4, 8, 13, 24.
A: The answer is True.

The odd numbers in this group add up to an even number: 17,  9, 10, 12, 13, 4, 2.
A: The answer is False.

The odd numbers in this group add up to an even number: 15, 32, 5, 13, 82, 7, 1. 
A: 
```

*出力：*

```
The answer is True.
```

それはうまくいきませんでした。このタイプの推論問題に対して信頼できる応答を得るには、数回のプロンプトだけでは十分ではないようです。上の例は、タスクに関する基本情報を提供します。詳しく見てみると、ここで紹介したタイプのタスクには、さらにいくつかの推論ステップが含まれています。言い換えれば、問題をいくつかのステップに分割し、それをモデルで実証すれば役立つかもしれません。最近では、[思考連鎖 (CoT) プロンプト](https://arxiv.org/abs/2201.11903)より複雑な算術、常識、記号推論のタスクに対処するために普及しました。

全体として、例を提供することはいくつかのタスクを解決するのに役立つようです。ゼロショット プロンプトや少数ショット プロンプトが十分でない場合は、モデルによって学習されたものだけではタスクをうまく実行するのに十分ではないことを意味している可能性があります。ここから、モデルを微調整するか、より高度なプロンプト手法を試してみることについて考え始めることをお勧めします。次に、非常に人気のある思考連鎖プロンプティングと呼ばれるプロンプト手法の 1 つについて説明します。
